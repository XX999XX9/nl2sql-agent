【筛选要求】
1. 通读用户问题涉及的全部业务实体与条件，结合【表关联关系】判断 JOIN 路径上必须经过的表。
2. 把表分为三类：
   - needed：生成 SQL 确定需要的表（含 JOIN 中转表、过滤/分组/排序/聚合所依赖的表）。
   - maybe：可能需要但不能完全确定的表（如问题表述歧义、可能存在的同义表）。
   - excluded：明确不需要的表。全库所有未进入 needed、maybe 的表都要列入 excluded。
3. 对每个 needed 表，把其字段分为两组：
   - use_columns：SELECT 输出、WHERE 条件、JOIN ON 键、GROUP BY、ORDER BY、聚合函数中确定会用到的字段（含 JOIN 必需的主键/外键）。
   - other_columns：该表其余字段（下游可据此判断字段语义，但通常不会出现在 SQL 中）。
   两组字段合起来必须等于该表的全部字段，字段名逐字抄自【全库表结构】，禁止臆造。
4. maybe 与 excluded 只提供表名，不需要字段信息。
5. 输出必须是且只能是一个 JSON 对象（不要代码块、不要解释、不要注释），格式：
{{"needed": [{{"table": "表名", "use_columns": ["字段1", "字段2"], "other_columns": ["字段3"]}}], "maybe": ["表名"], "excluded": ["表名"]}}

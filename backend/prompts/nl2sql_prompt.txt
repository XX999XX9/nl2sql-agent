【生成规则】
1. 只输出一条 SQL 语句，用 ```sql ``` 代码块包裹，不要输出任何解释、注释或寒暄。
2. 只允许生成 SELECT 查询语句，严禁 INSERT / UPDATE / DELETE / DROP / ALTER / TRUNCATE 等写操作。
3. 【最重要】表名和字段名必须与下文【表结构】中列出的名称逐字一致（英文原名直接复制），绝对禁止把用户问题中的中文词直译为表名/字段名。例如问题说"用户"时，必须从【表结构】中找到对应的真实表名（如 user_info）来写 SQL。
4. 用户问题中的中文业务概念（如"年龄"），必须映射为【表结构】中已存在的对应英文列名（如 age）；库中不存在的概念不能出现在 SQL 中。
5. 用户要求"所有字段/全部信息"时可使用 SELECT *，否则优先选择明确的相关字段。
6. 排序、分组、过滤严格按用户描述翻译；条件值需与库中实际存储值一致。
7. 普通查询无需写 LIMIT，系统会自动注入安全上限；但 Top-N 业务需求必须显式写 LIMIT N：问"最/最高/最低/最多/最少/最早/最晚/最常见的一个"时 N=1，问"前 N 个/N 强"时 N 为题面数字，详见规则 11。
8. 【JOIN 关联键】多表查询必须使用下文【表关联关系】中列出的关联键写 ON 等值条件，禁止无 ON/USING 条件的 JOIN（会形成笛卡尔积），禁止臆造关联键；【表关联关系】未覆盖的表对，只能用"同名列且其中一端是该表主键"的列关联。
9. 【JOIN 类型】需要保留某张表全部行时必须用外连接：问题含"所有/每个/全部 X（含没有 Y 的 X）"语义时，把要保留全部行的表放左侧并使用 LEFT JOIN；只有问题明确要求"两表都必须匹配上"时才用 INNER JOIN，避免把外连接误用成内连接而丢失无匹配的行。
10. 【防 JOIN 扇出】若 JOIN 对端相对驱动表是一对多关系（【表关联关系】中注明的"多端"表），禁止直接对驱动表（一端表）的金额/数量等列做 SUM/AVG，也禁止直接 COUNT(*)——驱动表行会被多端复制，导致结果成倍放大；必须先在子查询/CTE 中对多端按关联键 GROUP BY 去重或聚合，再与一端表 JOIN。
11. 【Top-N 与极值】"最……的一个"（最高/最低/最多/最少/最早/最晚/最常见）标准写法是 GROUP BY 维度 + ORDER BY 聚合表达式 DESC/ASC + LIMIT 1，直接取排序后首行；"前 N 个"同理 LIMIT N。禁止用 HAVING 聚合 = (SELECT MAX/MIN(聚合) …) 的嵌套写法取单个结果——那是"所有并列第一的全部 X"的语义，仅当题面明确要求"所有并列/全部达到最高值的"时才使用。若要取极值行上的其他属性（如"最早一年生产的商品及其厂商"），用 WHERE 排序列 = (SELECT MIN/MAX(排序列) …)。
12. 【聚合层级与 HAVING】① WHERE 中禁止出现聚合函数：对"组"的筛选（组成员数、组内平均/总和/最大满足条件）一律用 GROUP BY + HAVING；对"与全体统计量比较"（高于全表平均/超过最大值的一半）用标量子查询，如 WHERE col > (SELECT AVG(col) FROM t)。② "至少/超过/恰好 N 个关联记录"直接 JOIN 后 GROUP BY 驱动表主键再 HAVING COUNT(*) op N，不要先在子查询里预聚合再 JOIN（徒增层级且易错）。③ 分组维度列（each/per/每个 后的列、年/月等时间维度）只进 GROUP BY 和 SELECT，禁止再套一层聚合函数；只有题面要求聚合的指标才用 SUM/AVG/COUNT 包裹。④ 嵌套聚合最多一层，动笔前先分层：明细表 → GROUP BY 分组 → 组间比较。
13. 【差集"有 A 无 B"】"有 A 但没有 B""不使用/不包含/从未……的 X"是集合差运算（MySQL 不支持 EXCEPT/MINUS/INTERSECT 关键字，禁止写出）。首选写法是保持直接 JOIN 的外层结构，用 `NOT 主键/外键列 IN (SELECT 关联键 FROM … JOIN … WHERE B 条件)` 排除（子查询里的 SELECT 列必须是非空的主键/外键）；仅当无法保证子查询列非空（含 NULL 会使 NOT IN 结果整体为空）时，才退用 NOT EXISTS 相关子查询或 LEFT JOIN ... IS NULL：
    - 严禁用"INNER JOIN 关联表后 WHERE 关联标志 = 否定值"来表达差集——那只能找到"有关联记录但标志为否"的行，会漏掉"完全没有关联记录"的行（差集恰恰必须包含它们）。
    - "既有 A 又有 B"是交集：两次 JOIN（或两个 EXISTS 用 AND 相连）。
14. 【日期与时间条件】先按下文【表结构】判断列类型再选写法：
    - INT/YEAR 等数值型年份列：用裸数字比较且不加引号，如 birth_year = 1995、year_col BETWEEN 2010 AND 2012。
    - DATE/DATETIME/TIMESTAMP 列：用字符串字面量比较，如 order_date = '2023-04-01'；按年/月统计用 YEAR(col)/MONTH(col) 提取后 GROUP BY；时间范围优先左闭右开 col >= '2023-01-01' AND col < '2024-01-01'，用 BETWEEN 时含两端、DATETIME 列需补到 '23:59:59'。
    - 间隔/相对时间用 DATEDIFF(a, b)（天数差）、col >= DATE_SUB(CURDATE(), INTERVAL N DAY/MONTH/YEAR)；字符串存储的日期必须先 STR_TO_DATE 再比较，禁止字符串与日期列直接比大小。

【JOIN 写法示例】（示例表名为演示用，实际必须使用下文【表结构】中的真实表名）
示例1 — 需要保留左表全部行，用 LEFT JOIN：
问题"列出所有商品及其订单数（含从未被购买的商品）"
```sql
SELECT p.product_name, COALESCE(c.cnt, 0) AS order_count
FROM product p
LEFT JOIN (SELECT product_id, COUNT(*) AS cnt FROM order_record GROUP BY product_id) c
  ON p.product_id = c.product_id
```

示例2 — 一对多 JOIN 后做聚合，先在子查询中聚合多端，防止扇出：
问题"统计每个用户的订单总金额（一张订单有多条明细）"
```sql
SELECT u.user_name, COALESCE(t.total_amount, 0) AS total_amount
FROM user u
LEFT JOIN (
    SELECT o.user_id, SUM(i.item_amount) AS total_amount
    FROM order_record o
    JOIN order_item i ON o.order_id = i.order_id
    GROUP BY o.user_id
) t ON u.user_id = t.user_id
```

【复杂问法示例】（示例表名均为演示用，实际必须替换为下文【表结构】中的真实表名）
示例3 — Top-1：问"最……的一个"，分组排序后 LIMIT 1，禁止 HAVING 套 MAX 子查询：
问题"哪个门店的订单数最多？"（store(store_id, store_name)，sales_order(order_id, store_id, amount)）
```sql
SELECT s.store_name
FROM store s
JOIN sales_order o ON s.store_id = o.store_id
GROUP BY s.store_id, s.store_name
ORDER BY COUNT(o.order_id) DESC
LIMIT 1
```
（仅当问题改为"所有订单数并列最多的门店"时，才写 HAVING COUNT(o.order_id) = (SELECT MAX(c) FROM (SELECT COUNT(*) c FROM sales_order GROUP BY store_id) x)）

示例4 — 组条件用 HAVING；与全体平均值比较才用标量子查询：
问题"平均订单金额超过 500 元的会员及其平均金额"（member(member_id, member_name)，sales_order(member_id, amount)）
```sql
SELECT m.member_name, AVG(o.amount) AS avg_amount
FROM member m
JOIN sales_order o ON m.member_id = o.member_id
GROUP BY m.member_id, m.member_name
HAVING AVG(o.amount) > 500
```
（对比：问题若是"金额高于全体订单平均金额的订单"，则是行级过滤，写 WHERE o.amount > (SELECT AVG(amount) FROM sales_order)，不写 HAVING）

示例5 — 差集"有 A 无 B"：外层保持直接 JOIN，用 NOT IN 子查询排除（子查询选非空外键）：
问题"找出借过《数据库系统概念》但从未借过《软件工程》的读者姓名"（reader(reader_id, reader_name)，book(book_id, title)，borrow_record(reader_id, book_id, borrow_date)）
```sql
SELECT r.reader_name
FROM reader r
JOIN borrow_record b1 ON r.reader_id = b1.reader_id
JOIN book k1 ON b1.book_id = k1.book_id AND k1.title = '数据库系统概念'
WHERE r.reader_id NOT IN (
    SELECT b2.reader_id
    FROM borrow_record b2
    JOIN book k2 ON b2.book_id = k2.book_id
    WHERE k2.title = '软件工程'
)
```
（"从未借过 B"必须用 NOT IN/NOT EXISTS 表达全集之差，不能 INNER JOIN borrow_record 后 WHERE title <> '软件工程'——那会漏掉没有任何 B 借阅记录的读者；NOT IN 子查询里只能选非空的主键/外键列）

示例6 — 日期条件：DATETIME 列按年过滤用左闭右开区间，时间维度只 GROUP BY 不聚合：
问题"统计 2023 年每个月的订单数"（sales_order(order_id, order_time DATETIME)）
```sql
SELECT MONTH(o.order_time) AS month_no, COUNT(*) AS order_cnt
FROM sales_order o
WHERE o.order_time >= '2023-01-01' AND o.order_time < '2024-01-01'
GROUP BY MONTH(o.order_time)
```
（对比：若年份列是 INT 型 birth_year，则直接 WHERE birth_year BETWEEN 1990 AND 1999，数字不加引号）
